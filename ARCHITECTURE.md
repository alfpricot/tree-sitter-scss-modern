# tree-sitter-scss-modern architecture

tree-sitter-scss-modern is a [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for current
SCSS syntax. It is a fork of `tree-sitter-grammars/tree-sitter-scss` that adds the Sass module system
(`@use` and `@forward` options), maps, variable flags, boolean operators, and other syntax the original
does not parse, while keeping the original's node kinds so existing queries keep working.

The grammar is written in `grammar.js` as an extension of the `tree-sitter-css` grammar. `tree-sitter
generate` turns it into a C parser that is committed to the repository, so a consumer builds the parser
without installing the tree-sitter CLI. The Rust crate and the Node.js package are thin wrappers around that
one parser.

## What tree-sitter-scss-modern is not

- Not a Sass compiler or formatter: it produces a syntax tree and does not evaluate stylesheets.
- Not a replacement for the tree-sitter runtime: consumers bring their own `tree-sitter` package or crate.
- Not a separate node-kind vocabulary: node kinds and field names stay compatible with the upstream SCSS
  grammar, and `test/node-kinds.txt` records them so a change is visible in review.

## Major components

### [grammar.js](grammar.js)

The grammar definition. It extends `tree-sitter-css` and declares the two external tokens
(`_concat` and `_map_key`) that the scanner produces.

### [src/](src)

The generated parser (`parser.c`, `grammar.json`, `node-types.json`), committed so the bindings build
without the CLI, and `scanner.c`, the external scanner for the tokens the grammar cannot express alone.
Never edit the generated files by hand; regenerate them from `grammar.js`.

### [queries/](queries)

`highlights.scm`, the syntax-highlighting query that ships in both packages.

### [bindings/rust](bindings/rust)

The Rust crate: `lib.rs` exposes `LANGUAGE`, and `build.rs` compiles `src/parser.c` and `src/scanner.c`.

### [bindings/node](bindings/node)

The Node.js package: `binding.cc` is the native addon, `index.js` and `index.d.ts` are its entry point and
types, and `binding_test.js` and `queries_test.js` are its tests. `binding.gyp` at the root builds it, and
`node-gyp-build` prefers a matching prebuilt addon over a source build.

### [test/](test)

`corpus/` holds the tree assertions that `tree-sitter test` runs. `node-kinds.txt` is the committed
node-kind snapshot, regenerated by `generate-node-kinds.mjs`. `parse-rate.mjs` parses a directory of
stylesheets and reports files whose tree contains an error.

### [tools/](tools)

Scripts the release workflow runs: `release-policy.mjs` validates that a tag matches the `Cargo.toml`
version and sets package versions at publish time, and `package-check.mjs` checks the contents of the
packed packages. `release-policy.test.mjs` tests the policy script.

### [examples/](examples)

Stylesheets that CI parses to prove the grammar produces no `ERROR`, `MISSING`, or zero-width node.

## External systems and data flow

The grammar has no runtime dependencies on outside services. At build and release time it touches these:

- **crates.io, the public npm registry, and GitHub Packages** receive the published crate and packages
  (`.github/workflows/release.yml`). GitHub Packages publishes the npm package scoped to the repository
  owner, in its own checkout.
- **GitHub Releases** receive a WebAssembly build for `web-tree-sitter` consumers, plus
  `test/node-kinds.txt` and `versions.json`.

A consumer's data flow is: source text, then the `tree-sitter` runtime loads the language from this
package, then the parser and external scanner produce a syntax tree, then the consumer's queries read it.

## Build, test, release, and deploy

- **`verify.yml`** (`Verify`) runs on pull requests, on pushes to `dev` and `main`, and on demand. It
  regenerates the parser and fails on any difference in the generated files or `test/node-kinds.txt`, lints
  and format-checks the JavaScript, runs the corpus tests, parses every example, builds and tests the Rust
  and Node.js bindings, checks the packed package contents, validates the pull request title, scans for
  secrets, and lints workflow files. An aggregate job reports one `Verify` status for branch rules.
- **`release-plz.yml`** runs on pushes to `main` and opens a release pull request with the next version and
  `CHANGELOG.md`, computed from Conventional Commits.
- **`release-tag.yml`** tags the version when that release pull request merges and starts the release.
- **`release.yml`** publishes the crate and both npm packages for a `v*` tag, attaches the WebAssembly
  build, and creates the GitHub Release.
- **`sync-dev-from-main.yml`** opens a pull request that merges `main` back into `dev` after a release.
- **`cache-cleanup.yml`** deletes stale GitHub Actions caches daily.

Feature work lands on `dev`; `main` is the release branch. Nothing is deployed beyond the registries above.

| Path | Holds |

| `grammar.js` | The grammar definition |

| `bindings/rust/` | Rust crate source and build script |
